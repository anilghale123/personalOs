# Upgrade implementation notes

What shipped for `upgrade.md`, how to configure it, and how to test it.

## Environment variables

| Variable | Needed for | Notes |
| --- | --- | --- |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Password reset email | Port 465 = implicit TLS, 587 = STARTTLS. Gmail needs an **app password**, and `SMTP_FROM` must be that Gmail address (or a verified alias). |
| `RESEND_API_KEY`, `EMAIL_FROM` | Alternative to SMTP | Used only when `SMTP_HOST` is unset. |
| `PRO_EMAILS` | Optional Pro allowlist | Comma-separated. Admins/super admins always count as Pro. |
| `GROQ_WHISPER_MODEL` | Optional | Defaults to `whisper-large-v3-turbo`. Voice uses the existing `GROQ_API_KEY`. |

With no email provider in development, the reset email (including the code) is printed to the server console. In production it is refused.

After deploying, run `npm run db:indexes` to create the new indexes (`PasswordResetCode`, `Income`, and the `fingerprint` indexes on `Expense`).

## 1. Password reset (email code)

- `POST /api/password-reset` `{ email }` → `{ ok: true }`. The response is identical whether or not the account exists. Rate limits: 5 per hour per IP, 5 per hour per address, and one code per 60 s per account.
- `PUT /api/password-reset` `{ email, code, newPassword }` → `{ ok: true }`, or 400 `{ code: "invalid_code" }` for every kind of bad code.
- Codes are 6 digits and expire after 15 minutes. Each code allows 5 wrong attempts, and requesting a new code burns the old one. Only an HMAC keyed with `AUTH_SECRET` is stored. A successful reset revokes all sessions.
- UI: `/reset-password` (the "Forgot password?" link on the login form).

**Test:** open `/reset-password` and enter a registered email. The email arrives, or appears in the dev console. Enter the code and a new password, then sign in. Also check that an unknown email shows the same "check your email" screen, and that a wrong code shows "invalid or has expired".

## 2. Lean APIs

- `src/lib/dto.js` provides `pick` / `dto(fields)`, an allowlist response builder.
- Expense list, create, update, delete and undo responses (and the first-page server action) now return only `_id, amountPaisa, currency, categoryId, date, note, paymentMethod, tags, isRecurring, recurrence, autoGenerated, source, createdAt`. They no longer include `userId`, `__v`, `deletedAt` or `updatedAt`.
- The new feedback, admin feedback, income, voice and import endpoints return explicit shapes only.

## 3. Feedback and admin inbox

- `POST /api/feedback` `{ message, type?, email?, route?, viewport? }` works signed in or out. The user id comes from the session only.
- `GET /api/admin/feedback?status=new|read|archived|all&cursor=` returns `{ items, nextCursor }`.
- `PATCH /api/admin/feedback/:id` `{ status?, adminNote? }`.
- Admin UI: **/sysadmin/feedback**, protected by the existing role guard (non-admins get a 404). The "Send feedback" button is in the sidebar and on the login page.

## 4. Voice entry

- Expenses toolbar → **Voice**. Flow: record (MediaRecorder, max 15 s) → `POST /api/wealth/parse-voice` → editable confirm sheet → save through the normal expense or income API.
- The parser (`features/wealth/voice-parse.js`) is rule-based. It handles English and best-effort Nepali number words ("dui saya", "paanch hajar"). An LLM is used only when no amount is found.
- Fallbacks: browser `SpeechRecognition` when server transcription is unavailable, or typed text.
- **Pro only.** The Voice button is not rendered for free accounts, and the API returns 402 `pro_required`. Capped at 20 per hour and 50 per day per user. `Permissions-Policy` now allows `microphone=(self)`.
- Income is a new `Income` collection, kept separate so budget totals are unaffected. It appears in a new **Income** tab on Expenses.

## 5. Bank statement import (Pro)

- Expenses toolbar → **Import** → `/app/budget/import`.
- `POST /api/wealth/imports/parse` takes multipart `file` and optional `password`, and returns the header plus `transactions[]`. Rows already imported are flagged. The PDF is never stored.
- `POST /api/wealth/imports/commit` `{ bank, transactions }` → `{ created, skippedDuplicates }`. Withdrawals become expenses (`paymentMethod: bank_transfer`); deposits become income. Both get `source: "import:citizen-bank"`.
- Dedupe fingerprint: sha256 of date + direction + amount + normalised description + occurrence index. Identical same-day rows both import, and re-importing or overlapping statements are skipped.
- Adding a bank: create `features/wealth/imports/parsers/<bank>.js` exporting `{ id, label, detect, parse }`, then add it to `parsers/index.js`.
- Pro gating: `User.plan` (`free`/`pro`), which admins set in the new **Plan** column at /sysadmin/users. Also `PRO_EMAILS`, and admins. Free accounts don't see the Import button, `/app/budget/import` redirects them to Expenses, and the APIs return 402 `pro_required`.

**Test with a Citizens statement:** sign in as an admin (or set your plan to Pro), open `/app/budget/import` and upload the PDF. Check that the header, withdraw/deposit columns and suggested categories look right, and that opening/closing rows are not listed. Import, then upload the same PDF again: every row should show "Already imported", and committing reports them as skipped.

If a real statement parses badly, capture its extracted lines by calling `extractPdfLines` from `features/wealth/imports/pdf-text.js`. Add them, anonymised, as a fixture in `statement.test.js`. The parser is tested against fixture lines only; no real Citizens PDF was available during development.
